# Build instructions for AMO reviewers

The submitted package is produced by Vite, so the shipped JavaScript is
bundled and minified. These steps rebuild it byte-for-byte from this source.

## Environment

- Node.js 24.14.1 (any Node 20+ works; the lockfile pins every dependency)
- npm 11.11.0
- No other tooling, no network access needed beyond `npm ci`

## Build

```
npm ci
npm run build:firefox
```

That produces `dist-firefox/`, which is exactly what was uploaded. The command
is two steps:

1. `npm run build` — Vite builds the extension into `dist/` using the Chrome
   manifest generated by `@crxjs/vite-plugin` from `vite.config.ts`.
2. `node scripts/build-firefox.mjs` — copies `dist/` to `dist-firefox/` and
   applies the Gecko-specific changes. That script is short and readable; every
   transform is commented with its reason. In summary it:
   - adds `browser_specific_settings` (extension id, minimum versions, and
     `data_collection_permissions: none`)
   - rewrites `background.service_worker` to `background.scripts`, since
     Firefox MV3 uses an event page rather than a service worker
   - removes `use_dynamic_url` from web-accessible resources, which is
     Chrome-only
   - strips Vite's `crossorigin` attribute from `index.html` and `bubble.html`.
     Firefox treats it as a request for a CORS fetch, and a `moz-extension://`
     page requesting CORS for its own file is refused, so the popup would
     otherwise render blank.

## Notes on the two linter warnings you will see

`UNSAFE_VAR_ASSIGNMENT` appears ten times, all in the injected trading panel
(`src/content/x-inject.tsx`). The panel is built with `innerHTML` because it
renders inside a Shadow DOM on third-party pages.

Every interpolated value passes through the `esc()` helper defined at the top
of that file, which escapes `< > & "`. That covers all remote data: token
symbols and names from DexScreener, holder labels from GMGN, and any text that
originates off-device.

## Privacy

There is no backend. `manifest.json` `host_permissions` is the complete list of
servers the extension can contact, and every entry is a public third-party API
(chain RPCs, DexScreener, GeckoTerminal, GMGN, Jupiter, PumpPortal,
Bubblemaps). None is operated by us.

Keys are generated with `crypto.getRandomValues`, derived locally
(`@scure/bip39` + `@scure/bip32` for EVM, SLIP-0010 ed25519 for Solana), and
encrypted with PBKDF2 + AES-GCM via WebCrypto before being written to
`chrome.storage.local`. The decrypted key is held in `chrome.storage.session`
and cleared on lock. No code path passes a key, seed or mnemonic to a network
call — wallet creation works with the network disconnected.
